**Performance Tuning Note (AI-suggested optimizations)**
Each Ray change below was suggested by the AI after I ran the diagnostics that exposed the problem;
output parity was re-verified after each change (details in the report, Section 5):
1. Bucketed exact dedupe (shuffle on `pickup_seconds % 64`, local Arrow distinct) instead of a 19-column groupby.
2. Month-by-month dedupe after the global shuffle stalled for >3 h at full scale.
3. Pure-Arrow partitioned writer instead of `write_parquet(partition_cols=...)` (OOM).
4. `batch_size=250_000` and 64 MB target blocks (OOM from whole-block batches).
5. Bounded, content-hashed, atomically renamed checkpoint files (retry-safe).
6. One file per read task (`override_num_blocks`) after a single read task used 2.28 GB.
Spark tuning: `--executor-memory 2500m`, `--driver-memory 2g` (the default 1 GB driver heap caused an OOM).
